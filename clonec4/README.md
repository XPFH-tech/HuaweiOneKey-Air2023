# Clone C4 staged broad compatibility
C3 user verified Coolapk launch, u128 permission UI and component enabled. C4 merges C2 Settings and C3 system_server init hook. User explicitly scans and saves additive candidate snapshot (root-owned 0640, group system, /data/system, exact device gate, atomic write, readback and SELinux context guard). C4 reads it before PMS singleton publication, exact stock list guard, bounded validated set. No runtime mutation of published HashSet, no broad permission bypass, no system partition write, no auto installation, no auto enabling components or reboot. C3 fallback Coolapk only if snapshot unreadable; check logs because native cleanup could remove other clones. Back up all important clone data before enabling or disabling. Excludes system/updated system, non-launcher, disabled/suspended, root-related packages by known prefixes/strings, apps with device-admin/VPN/accessibility/notification listener service. This is not exhaustive security classification. Retains previous approved names even if later uninstalled to avoid automatic destructive cleanup; no automatic pruning. New app workflow: open C4, scan, save, soft restart, verify C4_ALLOWLIST_OK count. Not instant automatic or reboot-free. Settings attempts same snapshot, may be denied by SELinux and falls back to candidate listing; pending UI can differ from active server until reboot. Existing previously disabled clone launchers may require manual component enable, new app clone creation may work natively but not tested. Keep v0.4 and D3 unchanged. Install C4, stage list successfully before replacing C2 and C3 scopes, then backup and soft reboot. C4 scopes android + com.android.settings only. No raw user binaries committed.
